# 겹사진

안드로이드 갤러리에서 **같은 사진**을 찾아 한 무더기로 묶어 주는 앱입니다.
지우는 일은 하지 않습니다. 무엇을 지울지 고르는 것도, 지우기를 누르는 것도 사람이 합니다.

## 무엇을 같은 사진으로 보는가

| 경우 | 같은 사진인가 |
| --- | --- |
| 크기만 줄여 저장한 사본 | **그렇다** |
| 메신저로 보냈다가 다시 받아 화질이 상한 사본 | **그렇다** |
| 파일 이름이 전혀 다른 사본 | **그렇다** (이름은 아예 보지 않는다) |
| 같은 자리에서 찍은 다른 사진 | 기준에 따라 — 기본값에서는 아니다 |
| 구도는 같지만 색이 다른 사진 | 아니다 |

판단은 오직 사진의 생김새로 합니다. 파일 이름, 찍은 시각, 폴더는 보지 않습니다.
이름이 같아도 다른 사진일 수 있고, 이름이 달라도 같은 사진일 수 있기 때문입니다.

## 어떻게 알아보는가

사진을 32x32 짜리 작은 그림으로 줄인 뒤, 그 그림이 어떤 무늬로 이루어져 있는지를
64비트 숫자 하나(**지문**)로 적습니다. 크기가 다른 같은 사진은 줄여 놓으면 같은
그림이 되므로 같은 지문이 나옵니다.

여기에 두 가지를 더 두었습니다. 둘 다 만들면서 실제로 문제가 생겨 넣은 것입니다.

**첫째, 줄일 때 한 점도 버리지 않습니다.** 흔히 쓰는 이중선형 축소는 줄어든 픽셀
하나마다 원본의 이웃 네 점만 봅니다. 3000픽셀짜리 사진을 32픽셀로 줄이면 원본의
거의 모든 픽셀을 건너뛰게 되고, 어느 점이 하필 걸리느냐에 따라 지문이 달라집니다.
사진은 그래도 버텼지만 스크린샷처럼 경계가 또렷한 그림은 크기를 조금만 바꿔도
지문 절반이 뒤집혔습니다. 그래서 줄어든 픽셀 하나가 원본에서 맡은 **영역 전체의
평균**을 갖게 했습니다.

**둘째, 흔들리는 자리는 세지 않습니다.** 지문의 한 비트는 "이 무늬가 중앙값보다
센가" 라는 질문의 답인데, 값이 중앙값에 딱 붙어 있으면 그 답은 동전 던지기에
가깝습니다. 무늬가 적은 그림일수록 그런 자리가 많아집니다. 그래서 각 사진마다
믿을 수 있는 자리를 따로 적어 두고, 두 사진을 견줄 때 **양쪽 모두 믿을 수 있는
자리만** 봅니다. 무늬가 아예 없는 그림 — 로고나 단색 배경 위의 도형 — 은 지문을
포기하고 색으로 판단합니다. 그런 그림은 색이 아주 잘 갈라 줍니다.

색도 함께 봅니다. 사진을 4x4 칸으로 나눈 평균 색을 적어 두고, 지문이 가깝더라도
색이 다르면 다른 사진으로 봅니다. 같은 자리에서 찍은 낮 사진과 노을 사진이
한 무더기가 되지 않게 하는 장치입니다.

### 실제로 얼마나 갈리는가

`./gradlew test` 가 확인하는 것들입니다. 숫자는 64비트 중 다른 비트 수입니다.

| | 같은 사진끼리 | 다른 사진끼리 |
| --- | --- | --- |
| 사진 | 0 | 17 이상 |
| 스크린샷 | 0 | 10 이상 |
| 로고처럼 밋밋한 그림 | 색 거리 0~2 | 색 거리 10 이상 |

## 지우는 일에 대해

- 앱이 스스로 지우는 길은 **없습니다**. 코드에도 없습니다.
- "가장 좋은 한 장만 빼고 고르기" 는 **고르기만** 합니다.
- 지우기를 누르면 안드로이드가 확인창을 한 번 더 띄웁니다. 거기서 취소하면 아무 일도 없습니다.
- 기본은 **휴지통**입니다. 갤러리 휴지통에서 되돌릴 수 있습니다.
  되돌릴 수 없는 삭제는 설정에서 일부러 켜야 합니다.
- 남길 한 장은 화소가 가장 많고, 같다면 파일이 가장 큰 사진으로 제안합니다.
  마음에 들지 않으면 화면에서 직접 바꾸면 됩니다.

## 용량

정리해서 무엇을 얻는지 바로 보이게 했습니다.

- 사진마다 파일 크기가 그림 위에 적힙니다
- 무더기마다 "모두 24.1MB · 한 장만 남기면 19.3MB 비어요"
- 맨 위에 전체 합계, 무더기를 비울 수 있는 용량 순으로 정렬
- 고르는 동안 아래에 "4장 고름 · 지우면 9.1MB 비어요"

## 만들기

이 저장소에 밀어 넣으면 [GitHub Actions](../.github/workflows/android.yml) 가 검사하고
APK 를 만듭니다. 워크플로 실행 페이지의 **Artifacts → gyeopsajin-apk** 에서 내려받아
폰에 설치하면 됩니다(출처를 알 수 없는 앱 설치를 한 번 허용해야 합니다).

직접 만들려면 Android Studio 로 이 폴더를 열거나:

```bash
cd gyeopsajin
./gradlew test           # 같은 사진을 제대로 알아보는지 검사
./gradlew assembleDebug  # app/build/outputs/apk/debug/ 에 APK
```

안드로이드 11(API 30) 이상에서 동작합니다. 사진을 지울 때 시스템 확인창을 띄우는
방법이 그 버전부터 생겼기 때문입니다.

## 인터넷을 쓰지 않습니다

매니페스트에 인터넷 권한이 없습니다. 권한이 없으면 앱은 사진을 어디로도 보낼 수
없습니다. 지문은 기기 안의 데이터베이스에만 적히고, 백업에서도 제외됩니다.

## 폴더

```
gyeopsajin/
  app/src/main/java/io/github/gititit11/gyeopsajin/
    core/        같고 다름을 판단하는 부분 — 안드로이드와 무관한 순수 코틀린
    data/        갤러리 읽기, 지문 보관, 삭제 요청
    ui/          화면
  app/src/test/  core 검사 (JVM 에서 그대로 돌아간다)
```

`core/` 가 안드로이드에 기대지 않는 것은 일부러입니다. 그래야 기기 없이도
"리사이즈한 사진을 정말 같게 보는가" 를 실제 이미지로 검사할 수 있습니다.
