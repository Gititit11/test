# GymMate — 헬스 루틴 & 세트 체크 앱

> 이 저장소에는 앱이 두 개 있습니다.
> **GymMate**(이 문서, 저장소 루트) 와 **[마중물 — 물 마시기 기록 & 알림](majungmul/README.md)**(`majungmul/` 폴더).

머신·프리웨이트를 **검색**해서 나만의 헬스 루틴을 만들고, 운동 중에는 **한 세트를 끝낼 때마다 체크**하며 진행하는 웹앱입니다.
빌드 도구나 서버가 필요 없는 순수 HTML/CSS/JS로 만들어졌고, 모든 데이터는 브라우저(localStorage)에 저장됩니다.

## 실행 방법

```bash
# 1) 가장 간단한 방법 — index.html 을 브라우저로 열기
# 2) 로컬 서버로 실행 (오프라인 캐시·PWA 설치까지 사용하려면 권장)
npx http-server -p 8080 .
# → http://localhost:8080
```

## 안드로이드 휴대폰에서 앱처럼 쓰기

앱스토어에서 받는 앱이 아니라 **웹 주소를 홈 화면에 추가**하는 방식입니다.
홈 화면 설치와 오프라인 캐시는 **https 주소**에서만 동작하므로, GitHub Pages 로 올려두고 그 주소를 쓰면 됩니다.

> **먼저 확인:** GitHub Pages 는 비공개(private) 저장소에서는 유료 플랜에서만 동작합니다.
> 무료 계정이라면 **Settings → General → 맨 아래 Danger Zone → Change visibility → Public** 으로 바꿔야 합니다.

1. 저장소 **Settings → Pages → Source** 를 `GitHub Actions` 로 선택
2. 이 브랜치를 push 하면 `.github/workflows/pages.yml` 이 자동 배포
   (`Actions` 탭에서 초록 체크가 뜨면 완료 — 주소는 보통 `https://<계정>.github.io/test/`)
3. 안드로이드 **Chrome** 으로 그 주소를 열기
4. 주소창 오른쪽 `⋮` → **앱 설치** 또는 **홈 화면에 추가**

설치하면 주소창 없는 전체 화면으로 뜨고, 홈 화면에 덤벨 아이콘이 생깁니다.

### 파일 하나로 쓰기

```bash
node tools/build-single.js      # → dist/gymmate.html (CSS·JS 가 모두 들어간 단일 파일)
```

`dist/gymmate.html` 은 이 저장소에 함께 들어 있습니다. 이 파일 하나만 있으면 어디서든 열립니다.
단, 파일을 직접 여는 방식(`file://`)은 홈 화면 설치·오프라인 캐시가 적용되지 않고,
브라우저에 따라 저장이 초기화될 수 있으니 **기록을 계속 쌓을 목적이라면 위의 Pages 주소를 쓰세요.**

안드로이드에서 특히 신경 쓴 부분:

| 항목 | 내용 |
| --- | --- |
| 화면 꺼짐 방지 | 운동을 진행하는 동안 Screen Wake Lock 으로 화면이 꺼지지 않음 (운동 종료 시 자동 해제) |
| 백그라운드 타이머 | 화면을 끄면 브라우저가 타이머를 늦추므로, 남은 휴식은 **종료 시각 기준**으로 계산 — 돌아오면 항상 정확 |
| 앱 종료 복구 | Chrome 이 탭을 정리해도 진행 중인 세트 체크와 남은 휴식이 그대로 복구 |
| 숫자 키패드 | 무게·횟수·휴식 입력칸에 `inputmode` 지정 — 탭하면 바로 숫자 자판 |
| 알림음 | 모바일 정책에 맞춰 첫 터치 때 오디오를 활성화, 휴식 종료 시 알림음 + 진동 |
| 터치 영역 | 체크 버튼 44×44px, 하단 탭바는 제스처 바(safe-area) 만큼 여백 확보 |
| 오프라인 | 서비스워커가 모든 자산을 캐시 — 헬스장 지하에서도 그대로 동작 |

> 같은 와이파이의 PC에서 `npx http-server` 로 띄운 주소(`http://192.168.x.x:8080`)로도 접속은 되지만,
> http 는 보안 컨텍스트가 아니라 **설치·오프라인 캐시가 동작하지 않습니다.** 화면 확인용으로만 쓰세요.

## 주요 기능

### 1. 운동 검색 (내장 117종)
- 가슴 / 등 / 어깨 / 팔 / 하체 / 코어 / 유산소 × 머신 / 케이블 / 바벨 / 덤벨 / 스미스 / 맨몸 / 기타
- 한글 이름, 영문 이름, 자극 부위, 장비명으로 검색 (`랫풀다운`, `machine`, `광배근` 모두 가능)
- **초성 검색** 지원 — `ㅂㅊㅍ` → 벤치프레스, `ㅅㅋㅌ` → 스쿼트
- 부위·장비 필터 칩으로 좁혀 보기
- 원하는 운동이 없으면 **직접 추가**해서 내 운동 목록에 등록

### 2. 유산소
- 유산소는 세트로 끊지 않는다. 추가하면 **20분 1세트, 휴식 없음**으로 들어감 (인터벌은 편집에서 세트를 더하면 됨)
- 입력칸은 **기구가 알려주는 값만** 나온다. 라벨 붙은 격자로 표시

  | 운동 | 입력칸 | 계산 근거 |
  | --- | --- | --- |
  | 트레드밀 | 시간 · 속도(km/h) · 경사(%) | ACSM 걷기/달리기 공식 |
  | 사이클 · 로잉 머신 | 시간 · 와트(W) · 강도 | ACSM 에르고미터 공식 |
  | 일립티컬 · 스텝밀 · 줄넘기 · 배틀 로프 | 시간 · 강도 | 활동별 통용 MET |

- 속도가 걷기(6.4km/h 이하)인지 달리기(8km/h 이상)인지는 자동 판정. 그래서 **인클라인 워킹은 트레드밀에 합쳐졌다** (예전 기록은 그대로 열림)
- 강도는 **가볍게 / 보통 / 세게** 3단계. 고르지 않으면 보통으로 계산
- 와트를 적으면 그 값이 우선, 없으면 고른 강도로 계산
- 모든 계수는 보수적으로 0.85배
- 시간은 **분** 단위로 입력 (근력의 초 단위와 다름)
- 운동 중 유산소 카드에 지금까지 태운 열량이 표시됨

### 3. 성장 보기 (운동별 기록)
- 한 번이라도 한 운동을 최근 순으로 모아 보여 줌
- 운동을 고르면 **무게 추이**와 **횟수 추이**를 꺾은선으로 표시 (그 날 가장 무겁게 친 세트 기준)
- 최고 무게, 추정 1RM(Epley), 수행 횟수, 마지막 기록을 함께 표시
- 차트의 점을 누르면 그 날 기록이 보이고, 아래 날짜별 표에서 해당 운동 기록으로 이동
- 운동 중에는 각 운동 카드에 **지난번 기록**(무게 × 횟수)이 한 줄로 뜸

### 4. 루틴 만들기
- 루틴 카드 어디를 눌러도 바로 운동 시작 (운동이 없는 루틴은 편집 화면으로). 편집·복제·삭제는 카드 오른쪽 ⋮ 버튼 안에
- 카드에 운동 이름을 **5개까지** 보여주고 나머지는 `+N`. 이름은 **부위별 파스텔 색**으로 구분 (가슴·등·어깨·팔·하체·코어·유산소)
- 루틴 이름·메모 지정, 운동 순서 위/아래 이동, 복제·삭제
- 맨몸 운동(푸시업·풀업·버피 등)은 **무게 칸이 없다**. 횟수만 적으면 되고, 계산에 쓰는 체중은 설정에서 가져온다
- 성장 화면에서도 맨몸 운동은 무게 대신 **한 세트 최고 횟수 / 누적 횟수**를 보여준다
- 운동별로 **세트 수**와 **세트당 횟수·무게**를 개별 지정 (1세트 60kg×12, 2세트 70kg×10 처럼 세트마다 다르게 가능)
- `1세트 값으로 전체 채우기` 버튼으로 한 번에 정리
- 운동별 **휴식 시간**과 메모(핀 번호, 등받이 칸 등) 저장
- 플랭크·유산소 등은 횟수 대신 **시간(초)** 기준으로 기록

### 2.5 실행 인트로
앱을 **완전히 껐다 켰을 때만** 1.2초짜리 인트로가 뜹니다. 빈 봉에 안쪽 큰 원판이 먼저,
바깥쪽 작은 원판이 뒤따라 끼워지고, 다 끼우면 봉이 살짝 들립니다. 실제로 원판을 끼우는
순서와 같습니다.

- **뜨는 때 / 안 뜨는 때** — `sessionStorage` 로 가릅니다. 앱(탭)을 완전히 닫으면 지워지고,
  새로고침이나 안드로이드가 메모리에서 잠시 내렸다 복구할 때는 남습니다.
  그래서 *휴식 중에 유튜브 보고 돌아오는 것*과 *앱을 껐다가 다시 켜는 것*이 갈립니다

| 상황 | 인트로 |
|---|---|
| 앱을 완전히 종료 후 재실행 | 뜸 |
| 홈 버튼 → 다른 앱 → 돌아오기 | 안 뜸 |
| 새로고침 · 서비스워커 자동 갱신 | 안 뜸 |
| 운동 진행 중 | 안 뜸 |
| 기기에서 모션 줄이기를 켠 경우 | 안 뜸 |

- **앱을 늦추지 않습니다.** 앱은 덮개 아래에서 이미 다 그려져 있고 인트로는 그 위에
  올라갔다 사라집니다. 실제 대기 시간은 0입니다
- **아무 데나 누르면 즉시 걷힙니다.** 급할 때 붙잡히지 않아야 합니다
- 화면이 가려진 채 시간이 흐르면 타이머가 밀리므로, 돌아왔을 때 **남은 시간을 다시 재서**
  겁니다. 무조건 닫으면 안 됩니다 — 아이폰 홈 화면 앱은 실행 직후 `visibilitychange` 가
  한 번 오는데, 그걸 "돌아왔다" 로 읽으면 시작하자마자 인트로가 꺼집니다
- **버전 확인을 여기에 얹었습니다.** 인트로가 도는 동안 서비스워커가 새 버전을 확인합니다.
  어차피 기다리는 1.2초라 사용자가 따로 기다릴 일이 없습니다. 화면에는 아무것도 알리지 않습니다
- markup 과 제어를 **모두 `index.html`** 에 두었습니다. 첫 페인트에 바로 나와야 하고,
  무엇보다 **`app.js` 가 죽어도 덮개가 반드시 걷혀야** 하기 때문입니다
- 인트로가 앱을 막는 일이 없도록 세 겹으로 막아 뒀습니다
  1. 덮개는 `pointer-events: none` — 남아 있어도 터치를 가로채지 않습니다
  2. 애니메이션 시간을 CSS 에 직접 적습니다. `var()`/`calc()` 로 받으면 그 값이
     안 오는 순간 애니메이션이 멈춰 검은 화면이 남습니다
  3. 3초 뒤 통째로 DOM 에서 지우는 그물이 하나 더 있습니다
- **앱 아이콘과 같은 아령입니다.** 아이콘은 인트로와 똑같은 좌표·색으로 `tools/build-icons.js`
  가 만듭니다. 인트로 모양을 고치면 그 스크립트의 `PLATES` 도 같이 고치고 다시 돌리세요

```
node tools/build-icons.js            # 아이콘 4종 + 원본 SVG 2종을 다시 만든다
node tools/build-icons.js --preview  # icons/ 를 건드리지 않고 미리보기만
```
- 타이밍: 봉 0–192ms · 안쪽 원판 144–456ms · 바깥 원판 336–648ms · 봉 들림 600–960ms ·
  워드마크 744–1056ms · 덮개 걷힘 1056–1200ms

### 3. 운동 중 세트 체크
- 세트마다 큼직한 체크 버튼 — 누르면 완료 처리되고 **휴식 타이머가 자동 시작**
- 휴식 종료 시 알림음 + 진동 + **안내 음성** ("휴식 시간이 종료되었습니다. 운동을 시작해주세요.")
  - `audio/` 에 동봉한 mp3 3종(`Ash`·`Ivy`·`Winter`) 중에서 고르거나 끌 수 있습니다.
    설정에서 ▶ 로 들어보고 선택하세요
  - 알림음과 같은 Web Audio 경로로 재생합니다. `<audio>` 로 재생하면 안드로이드가
    듣던 음악을 아예 멈출 수 있어서입니다
  - 서비스워커가 mp3 도 캐시하므로 오프라인에서도 나옵니다
  - **안내음 음량**을 0~100% 로 조절할 수 있습니다 (알림음·안내 목소리 공통)

#### 음악과 같이 들을 때
동봉 mp3 는 RMS 가 -18.5dBFS 인데 스트리밍 음악은 대개 -12~-9dBFS 라 6~10dB 밀립니다.
그래서 음악을 틀어 두면 안내음이 거의 안 들렸습니다.

파형을 일그러뜨리지 않는 방법만 씁니다.

| 단계 | 하는 일 |
|---|---|
| 150Hz 하이패스 2단 | 말에는 거의 없고 음악에는 많은 저역을 덜어냅니다. 최고점이 낮아져 그만큼 전체를 더 키울 수 있습니다 |
| 2kHz 하이쉘프 +6dB | 말이 알아들리는 대역이자 귀가 가장 예민한 구간. 전체를 키우는 것보다 여기를 키우는 쪽이 음악을 잘 뚫습니다 |
| 최고점 정규화 | 최고점을 0.97 로 맞추는 단순 곱셈 |

- 결과(세 목소리 모두 같음): 전체 RMS **-18.7 → -13.1dBFS**,
  말이 들리는 2~5kHz 대역 **-30.1 → -22.1dB**. 최고점이 0.97 로 통일돼 목소리 사이
  편차도 없습니다
- 알림음은 990Hz **삼각파**입니다. 순수 사인파는 음악에 묻히고 사각파는 그 자체가
  거칠어서, 배음이 있으면서 빠르게 줄어드는 삼각파를 씁니다
- 진동은 알림음 설정과 무관하게 항상 울립니다. 소리가 묻혀도 이건 남습니다
- **음악 소리 자체를 줄이는 것(오디오 포커스 요청)은 웹 페이지가 할 수 없습니다.**
  100% 가 낼 수 있는 가장 큰 소리이고, 그래도 묻히면 음악 쪽을 줄여야 합니다

##### 시도했다가 접은 것
- **tanh 포화** — 파형을 눌러 평균을 8dB 올렸습니다. 커지긴 했지만 파형 자체를
  찌그러뜨리는 방식이라 배음이 생겨 "치지직" 하는 파열음으로 들렸습니다.
  크기를 얻는 대신 음질을 판 셈이라 접었습니다
- **압축기·리미터** — 문턱값을 -3dB 부터 -32dB 까지 훑어봤지만 이 파일들은
  최고점이 뾰족하지 않아(파고율 12.7dB, 대부분이 말소리) 깎을 봉우리가 없습니다.
  오히려 평균이 내려갔습니다(-13.8 → -15.0dBFS)
- **재생 그래프의 DynamicsCompressor** — 부드러운 압축기라 천장을 못 잡아 100% 에서
  +1.2dBFS 로 잘렸고, 맨 뒤로 옮기니 50% 와 100% 가 1.2dB 밖에 차이 나지 않아
  음량 조절이 사실상 죽었습니다

왜곡 없이 얻을 수 있는 한계가 RMS -13dBFS 부근입니다. 그 위는 음질을 팔아야 합니다.

- `+15초 / -15초 / 건너뛰기`
- **운동 중에도 휴식 시간을 바로 수정** — 운동 카드의 `휴식 [90] 초` 칸을 고치면 오늘 운동과 원래 루틴에 함께 반영
- 화면을 끄거나 다른 앱을 보다 돌아와도 남은 휴식 시간이 정확 (종료 시각 기준 계산), 앱을 껐다 켜도 휴식이 이어짐
- 진행률 바, 경과 시간, 실시간 총 볼륨(무게×횟수) 표시
- 실제로 든 무게·횟수가 계획과 다르면 그 자리에서 수정 후 체크
- 운동 중 세트 추가/삭제 가능
- 진행 상태가 즉시 저장되어 **앱을 닫았다 열어도 이어서** 진행

### 4. 기록 · 근육 지도
- 완료한 운동은 날짜·소요 시간·완료 세트 수·총 볼륨과 함께 저장 (체크하지 않은 세트는 제외)
- 최근 7일 요약 5칸: 운동 횟수 · 칼로리 · 볼륨(기구 kg) · 총 횟수 · 누적 운동 횟수
  - **7일 총 횟수**는 최근 7일 안에 시작한 기록에서 체크한 세트의 반복 횟수를 모두 더한 값입니다
    (60kg × 10회 × 3세트 = 30). 시간으로 하는 운동(유산소·플랭크)은 횟수가 없어 세지 않습니다
  - 볼륨은 무게 × 횟수라 맨몸 운동이 구조적으로 0 이라서, 무게와 무관한 작업량을 같이
    보여주려고 둔 칸입니다. 무게를 무시하므로 볼륨과 짝으로 봐야 뜻이 있습니다
  - 세트를 셀 때 `done` 이 명시적으로 `false` 인 것만 안 한 세트로 봅니다. 볼륨·총 횟수·
    세트 수가 모두 같은 기준을 씁니다
- **최근 7일 부위별 운동량을 인체 그림(앞·뒤)에 표시** — 부위마다 정해진 주당 볼륨 기준과 견줘 판정
  - 운동의 주동근은 1세트, 보조근은 0.4세트로 계산 (벤치프레스 1세트 = 가슴 1 + 삼두 0.4 + 어깨 0.4)
  - 승모근·어깨·가슴·등(광배)·허리·이두·삼두·전완·복근·복사근·둔근·대퇴사두·햄스트링·종아리 14개 부위
  - 그림이나 목록에서 부위를 누르면 세트 수·볼륨·기준선·다음에 할 일·많이 한 운동 확인
  - 목록에는 14개 부위를 모두 싣는다. 이번 주에 빠뜨린 부위가 가장 중요한 정보다

#### 볼륨 랜드마크 (색을 정하는 기준)
부위마다 주당 세트 수의 기준선 넷을 두고 여섯 구간으로 판정합니다.

| 약어 | 뜻 |
|---|---|
| MV  | 근육량을 유지만 하는 데 필요한 최소 세트 수 |
| MEV | 실제로 성장이 일어나기 시작하는 최소 볼륨 |
| MAV | 회복 가능한 범위에서 가장 효율적으로 성장하는 구간 |
| MRV | 이 이상은 회복이 안 돼 역효과가 나는 한계치 |

| 구간 | 색 | 뜻 |
|---|---|---|
| 안 함 | 흰색 | 이번 주에 하지 않음 |
| 부족 (< MV) | 옅은 노랑 | 유지에도 못 미침 |
| 유지 (MV~MEV) | 옅은 청록 | 줄지는 않지만 성장 자극은 없음 |
| 성장 (MEV~MAV) | 청록 | 성장이 일어나는 구간 |
| 최적 (MAV~MRV) | 진한 청록 | 가장 효율이 좋은 구간 |
| 초과 (> MRV) | 빨강 | 회복 한계를 넘음 |

- 많이 할수록 좋은 값이 아니라 **모자라도 넘쳐도 나쁜 값**이라, 가운데(유지~최적)를
  청록 램프로 두고 양 끝에 경고색을 하나씩 뒀습니다 — 부족은 노랑, 초과는 빨강
- 기준값은 `js/bodymap.js` 의 `GROUPS` 에 부위별로 적혀 있습니다. 문헌의 일반
  권장치(Israetel 계열)라 개인차가 크고, 우리 세트 수는 보조근을 0.4로 세는
  가중치라 직접 세트만 세는 원 표와 완전히 같지는 않습니다
- 예전에는 "그 주에 가장 많이 한 부위"를 100%로 잡는 상대 척도였습니다. 그래서
  가볍게 한 주와 몰아친 주가 똑같이 진하게 나왔습니다. 지금은 절대 기준이라
  주마다 색을 비교할 수 있습니다
- 색 검증(카드 표면 `#1b2029` 기준): 청록 램프 명도 단조·인접 ΔL 0.09~0.10·단일 색조,
  부족·초과와 나머지 모든 구간의 색약(적색약·녹색약) ΔE 11.6 이상·정상시각 15.3 이상,
  여섯 색 모두 표면 대비 4:1 이상.
  구간은 색만으로 전해지지 않으므로 범례·목록·상세에 이름을 함께 적습니다
  - 인체 도해는 [body-muscles](https://github.com/vulovix/body-muscles)(Apache-2.0)의 경로를 사용합니다.
    고지와 변경 내용은 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) 참고
- 기록 상세에서 세트별 무게·횟수 확인

### 5. 칼로리 추정

설정에 체중을 넣으면 운동 중·기록·7일 합계에 추정 소모 열량이 표시됩니다.

**계산 방식** — 기초 구간 + 역학적 일

```
kcal = 휴식 대사량 × 운동 시간
     + Σ (들어올린 무게 × 9.81 × 가동거리 × 횟수 × 신장성 가산) ÷ 4184 ÷ 효율
     + Σ (시간형 운동 MET − 휴식 MET) × 3.5 × 체중 ÷ 200 × 분
```

순수 MET 방식은 무게가 결과에 들어가지 않아 40kg 벤치와 100kg 벤치가 같은 값이 나옵니다.
역학적 일 항을 섞어 증량이 반영되게 했습니다. 운동 시간은 세트를 체크한 시각(`doneAt`)
기준으로 잡아, 앱만 켜두고 쉰 시간은 세지 않습니다.

**계수는 통용값보다 소모가 적게 나오는 쪽으로 잡았습니다.**

| 계수 | 일반적인 값 | 이 앱 |
| --- | --- | --- |
| 휴식 MET | 2.0 (서서 쉬기) | 1.8 |
| 신장성 수축 가산 | ×1.3 | ×1.2 |
| 근수축 효율 | 0.20~0.25 | 0.25 (높을수록 소모 적음) |
| 가동거리 | 운동별 실측 | 넉넉하지 않게 하향 |
| 유산소 MET | 러닝 9~11 | 8.0 |
| EPOC(운동 후 대사 상승) | 세션의 5~15% | 미적용 |

결과는 체중 80kg 기준 웨이트 트레이닝 **3.3~4.1 kcal/분** 범위로, 실측 문헌값(3~5 kcal/분)의
아래쪽에 놓입니다. 측정이 아닌 추정이며 실제와 ±20~30% 차이가 날 수 있습니다.

### 6. 설정
- 무게 단위(kg/lb), 기본 휴식 시간(새로 담는 운동에 적용), 알림음 on/off, 안내음 음량, 안내 목소리, 체중
- 내가 추가한 운동 관리
- 백업 — 내용 **복사하기**(어디서나 동작) 또는 **파일로 저장**, 되돌릴 때는 파일 선택 또는 **붙여넣기로 가져오기**
- 전체 초기화
