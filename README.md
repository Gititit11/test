# 앱 두 개가 들어 있는 저장소

GitHub Pages 로 배포하면 주소 하나에 앱 두 개가 올라갑니다.
루트는 둘 중 하나를 고르는 안내 페이지입니다.

| 주소 | 앱 | 문서 |
| --- | --- | --- |
| `/test/` | 앱 고르기 (안내 페이지) | — |
| `/test/gymmate/` | **짐메이트** — 헬스 루틴 & 세트 체크 | [gymmate/README.md](gymmate/README.md) |
| `/test/majungmul/` | **마중물** — 물 마시기 기록 & 알림 | [majungmul/README.md](majungmul/README.md) |

```bash
npx http-server . -p 8080 --silent
# → http://localhost:8080/            앱 고르기
# → http://localhost:8080/gymmate/    짐메이트
# → http://localhost:8080/majungmul/  마중물
```

## 왜 앱마다 폴더를 나눴나

설치형 웹앱(PWA)은 자기 **영역(scope)** 을 선언하는데, 그 영역은 매니페스트가
놓인 위치를 기준으로 잡힙니다. 짐메이트가 루트에 있을 때 영역이 `/test/` 전체였고,
그 안에 있던 마중물이 **짐메이트 앱의 한 페이지로 취급**됐습니다.
안드로이드 크롬에서 마중물을 설치하려 하면 "이미 설치됨" 이 뜨고,
링크를 눌러도 짐메이트 앱 창으로 열리는 문제가 있었습니다.

그래서 앱마다 폴더를 하나씩 갖게 하여 영역을 갈랐습니다.

```
/test/            안내 페이지 (설치하지 않음)
/test/gymmate/    짐메이트 영역
/test/majungmul/  마중물 영역
```

매니페스트의 `id` 는 적지 않습니다. 적지 않으면 `start_url` 이 그대로 앱의 신원이
되어 실제 주소와 항상 일치합니다. 예전에는 실제 주소와 다른 값(`/gymmate/`)이
적혀 있어, 브라우저가 "이미 설치된 앱인가" 를 잘못 판단할 여지가 있었습니다.

> 짐메이트 주소가 `/test/` 에서 `/test/gymmate/` 로 바뀌었습니다.
> 예전 아이콘은 안내 페이지로 열리며, 거기서 다시 설치하면 됩니다. 기록은 그대로 남습니다.
> 루트의 `sw.js` 는 예전 주소에 남아 있던 서비스워커를 스스로 걷어내는 역할만 합니다.

## 배포

`.github/workflows/pages.yml` 이 저장소 전체를 GitHub Pages 로 올립니다.
푸시된 브랜치의 파일이 그대로 사이트가 되므로, 두 앱은 같은 브랜치에 함께 있어야 합니다.
